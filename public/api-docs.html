Dokumen gue Kumpulan Editor

API

Tarik daftar short link dokumen lo secara programatik. Tukar credentials akun jadi token, lalu pakai token itu buat akses.

Base URL · https://markdown.hanif.app

Alur

  1. Ambil token — kirim email + password ke /api/v1/auth/token, dapet token Bearer (berlaku 30 hari).
  2. Pakai token — sertakan di header Authorization: Bearer <token> buat akses endpoint lain.

Token = sesi akun. Simpan aman; siapa pun yang pegang token bisa akses dokumen lo. Mau cabut? Logout dari web ga nyabut token API — token kedaluwarsa sendiri setelah 30 hari (idle).

1 · Ambil token

POST/api/v1/auth/token

Request body (JSON)

FieldTipeKeterangan
emailstringEmail akun
passwordstringPassword akun

Contoh

curl -X POST https://markdown.hanif.app/api/v1/auth/token \
  -H 'Content-Type: application/json' \
  -d '{"email":"kamu@email.com","password":"••••••••"}'

Response 200

{
  "token": "OxkWH3Xcb73-hc8rpuabdTNoxwrtr8y9",
  "token_type": "Bearer",
  "expires_in": 2592000,
  "user": { "email": "kamu@email.com" }
}

Salah email/password → 401 { "error": "Email atau password salah." }

2 · Push — bikin dokumen baru

Kirim markdown, langsung dapet short link. Bisa sekalian set slug (custom link), theme, font, dan passcode.

POST/api/v1/docs

Request body (JSON)

FieldTipeKeterangan
contentstringWajib. Isi markdown
slugstringOpsional — custom link (3–50 char, a-z 0-9 -)
theme · fontstringOpsional — default light · serif
passcodestringOpsional — kunci dokumen

Contoh

# push file md, kasih custom link "rilis-notes"
curl -X POST https://markdown.hanif.app/api/v1/docs \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d "{\"slug\":\"rilis-notes\", \"content\": $(jq -Rs . < notes.md)}"

Response 201

{
  "id": "k7p2q9m4a",
  "url": "https://markdown.hanif.app/rilis-notes",
  "slug": "rilis-notes",
  "has_passcode": false
}

Slug udah dipakai → 409. Format slug salah → 400.

3 · List short link

GET/api/v1/docs

Header

Authorization: Bearer <token>

Contoh

curl https://markdown.hanif.app/api/v1/docs \
  -H "Authorization: Bearer $TOKEN"

Response 200

{
  "count": 2,
  "docs": [
    {
      "id": "m25qh4fjy",
      "title": "Catatan A",
      "url": "https://markdown.hanif.app/catatan-a",
      "slug": "catatan-a",
      "has_passcode": false,
      "theme": "light",
      "font": "serif",
      "views": 12,
      "created_at": 1780632162730,
      "updated_at": 1780632162742
    }
  ]
}

Field per dokumen

FieldTipeKeterangan
idstringID dokumen
titlestringJudul (dari heading pertama)
urlstringShort link siap pakai (pakai slug kalau ada, kalau ga /d/<id>)
slugstring·nullCustom URL, null kalau belum diset
has_passcodebooleanDokumen dikunci passcode atau ga
theme · fontstringTema & font dokumen
viewsnumberJumlah view
created_at · updated_atnumberEpoch milidetik

Token invalid/kadaluwarsa → 401 { "error": "Token tidak valid atau kadaluarsa." }

Termasuk konten markdown mentahnya. Bisa pakai id atau slug.

  }

5 · Replace / edit dokumen

Ganti isi dokumen dengan markdown baru — link-nya tetap sama (id & slug ga berubah). Bisa pakai id atau slug.

PUT/api/v1/docs/<id-atau-slug>

Request body (JSON)

FieldTipeKeterangan
contentstringWajib. Markdown baru (replace penuh)
themestringOpsional — kalau ga dikirim, tema lama dipertahankan
fontstringOpsional — kalau ga dikirim, font lama dipertahankan

Contoh

# replace isi dokumen "catatan-a" dengan file md baru
curl -X PUT https://markdown.hanif.app/api/v1/docs/catatan-a \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d "{\"content\": $(jq -Rs . < catatan-baru.md)}"

Response 200

{
  "ok": true,
  "id": "m25qh4fjy",
  "url": "https://markdown.hanif.app/catatan-a",
  "slug": "catatan-a",
  "title": "Catatan A (v2)",
  "updated_at": 1780640000000
}

Cuma bisa edit dokumen milik akun pemegang token. Bukan punya lo → 401/404. Passcode & slug ga keganti pas replace.

6 · Custom link

Set / ganti / hapus custom link dokumen yang udah ada. Kirim slug kosong buat balik ke link acak.

PUT/api/v1/docs/<id-atau-slug>/slug
curl -X PUT https://markdown.hanif.app/api/v1/docs/k7p2q9m4a/slug \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"slug":"link-baru"}'
{ "ok": true, "slug": "link-baru", "url": "https://markdown.hanif.app/link-baru" }

Udah dipakai → 409. Format salah → 400.

7 · Hapus dokumen

DELETE/api/v1/docs/<id-atau-slug>
curl -X DELETE https://markdown.hanif.app/api/v1/docs/link-baru \
  -H "Authorization: Bearer $TOKEN"
{ "ok": true }

8 · Upload gambar

Upload gambar ke storage (Cloudflare R2), dapet URL publik yang bisa lo embed ke markdown pakai ![alt](url). Body request = raw bytes gambar (bukan multipart/form-data), dan header Content-Type harus tipe gambarnya.

POST/api/v1/images

Header

HeaderKeterangan
AuthorizationWajib. Bearer <token>
Content-TypeWajib. Tipe gambar: image/png, image/jpeg, image/gif, image/webp, atau image/avif

Maks 10 MB. SVG ga didukung (alasan keamanan).

Contoh

# upload foto.png (perhatiin: --data-binary + Content-Type tipe gambar)
curl -X POST https://markdown.hanif.app/api/v1/images \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: image/png" \
  --data-binary @foto.png

Response 201

{ "url": "https://img.hanif.app/u3k2.../a8Fk2mZ9.png" }

Alur lengkap: upload gambar lalu push markdown

# 1. upload gambar, ambil URL-nya
IMG=$(curl -s -X POST https://markdown.hanif.app/api/v1/images \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: image/png" \
  --data-binary @diagram.png | jq -r .url)

# 2. push markdown yang nyisipin gambar itu
curl -X POST https://markdown.hanif.app/api/v1/docs \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d "{\"content\": $(jq -Rs . <<EOF
# Laporan

![diagram]($IMG)
EOF
)}"

Tipe ga didukung → 415. File kosong → 400. Kegedean → 413. R2 belum dikonfigurasi → 503.

9 · Kumpulan dokumen (dir)

Kelompokin beberapa dokumen jadi satu "dir", lalu bagikan satu link: https://markdown.hanif.app/dir/<slug> — halaman index berisi semua dokumen di dalamnya (publik; dokumen ber-passcode tetap ke-gate pas diklik). Satu dokumen boleh masuk ke beberapa dir.

Bikin dir

POST/api/v1/dirs
FieldTipeKeterangan
slugstringWajib. URL dir (3–50 char, a-z 0-9 -). Reachable di /dir/<slug>
titlestringOpsional — judul halaman
descriptionstringOpsional — intro (boleh markdown), dirender di atas daftar
theme · fontstringOpsional — tampilan halaman dir
docIdsstring[]Opsional — isi awal (id atau slug dokumen milik lo)
curl -X POST https://markdown.hanif.app/api/v1/dirs \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"slug":"tiktok","title":"Semua soal TikTok","docIds":["catatan-a","k7p2q9m4a"]}'
{
  "id": "au4dnvdac",
  "slug": "tiktok",
  "url": "https://markdown.hanif.app/dir/tiktok",
  "title": "Semua soal TikTok",
  "description": null,
  "theme": "light", "font": "serif",
  "doc_count": 2,
  "docs": [ { "id": "...", "title": "...", "url": "...", "position": 0 } ]
}

Slug dipakai dir lain → 409. Format salah/reserved → 400. Slug dir punya namespace sendiri (/dir/...), jadi ga bentrok sama custom link dokumen.

List / ambil dir

GET/api/v1/dirs
GET/api/v1/dirs/<id-atau-slug>

GET /api/v1/dirs balikin ringkasan semua dir + doc_count. GET /api/v1/dirs/<id-atau-slug> balikin 1 dir + array docs lengkap (urut posisi).

Tambah / keluarin dokumen

POST/api/v1/dirs/<id-atau-slug>/docs
DELETE/api/v1/dirs/<id-atau-slug>/docs/<doc-id-atau-slug>
# tambah 1 dokumen ke dir
curl -X POST https://markdown.hanif.app/api/v1/dirs/tiktok/docs \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"docId":"k7p2q9m4a"}'
{ "ok": true, "added": true, "docs": [ ... ] }

Body docId bisa id atau slug, harus dokumen milik lo. Udah ada → added:false (idempoten).

Urutan & metadata

PUT/api/v1/dirs/<id-atau-slug>
PUT/api/v1/dirs/<id-atau-slug>/slug
PUT/api/v1/dirs/<id-atau-slug>/docs

PUT /api/v1/dirs/<…> update title/description/theme/font (field yang ga dikirim dipertahankan). /slug ganti URL dir. /docs dengan body {"docIds":[...]} set ulang urutan tampil.

Hapus dir

DELETE/api/v1/dirs/<id-atau-slug>
{ "ok": true }

Cuma hapus grup-nya — dokumen di dalamnya ga ikut kehapus.

Catatan

  • Semua request JSON pakai Content-Type: application/json — kecuali upload gambar (raw bytes, lihat #8).
  • Endpoint /api/v1/auth/token di-rate-limit (anti brute force).
  • Field url udah absolut & siap dibagikan — ga perlu nyusun sendiri.
