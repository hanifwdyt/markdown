Markdown.hanif.app
Dokumen gue Editor

API

Tarik daftar short link dokumen lo secara programatik. Tukar credentials akun jadi token, lalu pakai token itu buat akses.

Base URL · https://markdown.hanif.app

Alur

  1. Ambil token — kirim email + password ke /api/v1/auth/token, dapet token Bearer (berlaku 30 hari).
  2. Pakai token — sertakan di header Authorization: Bearer <token> buat akses endpoint lain.

Token = sesi akun. Simpan aman; siapa pun yang pegang token bisa akses dokumen lo. Mau cabut? Logout dari web ga nyabut token API — token kedaluwarsa sendiri setelah 30 hari (idle).

1 · Ambil token

POST/api/v1/auth/token

Request body (JSON)

FieldTipeKeterangan
emailstringEmail akun
passwordstringPassword akun

Contoh

curl -X POST https://markdown.hanif.app/api/v1/auth/token \
  -H 'Content-Type: application/json' \
  -d '{"email":"kamu@email.com","password":"••••••••"}'

Response 200

{
  "token": "OxkWH3Xcb73-hc8rpuabdTNoxwrtr8y9",
  "token_type": "Bearer",
  "expires_in": 2592000,
  "user": { "email": "kamu@email.com" }
}

Salah email/password → 401 { "error": "Email atau password salah." }

2 · Push — bikin dokumen baru

Kirim markdown, langsung dapet short link. Bisa sekalian set slug (custom link), theme, font, dan passcode.

POST/api/v1/docs

Request body (JSON)

FieldTipeKeterangan
contentstringWajib. Isi markdown
slugstringOpsional — custom link (3–50 char, a-z 0-9 -)
theme · fontstringOpsional — default light · serif
passcodestringOpsional — kunci dokumen

Contoh

# push file md, kasih custom link "rilis-notes"
curl -X POST https://markdown.hanif.app/api/v1/docs \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d "{\"slug\":\"rilis-notes\", \"content\": $(jq -Rs . < notes.md)}"

Response 201

{
  "id": "k7p2q9m4a",
  "url": "https://markdown.hanif.app/rilis-notes",
  "slug": "rilis-notes",
  "has_passcode": false
}

Slug udah dipakai → 409. Format slug salah → 400.

3 · List short link

GET/api/v1/docs

Header

Authorization: Bearer <token>

Contoh

curl https://markdown.hanif.app/api/v1/docs \
  -H "Authorization: Bearer $TOKEN"

Response 200

{
  "count": 2,
  "docs": [
    {
      "id": "m25qh4fjy",
      "title": "Catatan A",
      "url": "https://markdown.hanif.app/catatan-a",
      "slug": "catatan-a",
      "has_passcode": false,
      "theme": "light",
      "font": "serif",
      "views": 12,
      "created_at": 1780632162730,
      "updated_at": 1780632162742
    }
  ]
}

Field per dokumen

FieldTipeKeterangan
idstringID dokumen
titlestringJudul (dari heading pertama)
urlstringShort link siap pakai (pakai slug kalau ada, kalau ga /d/<id>)
slugstring·nullCustom URL, null kalau belum diset
has_passcodebooleanDokumen dikunci passcode atau ga
theme · fontstringTema & font dokumen
viewsnumberJumlah view
created_at · updated_atnumberEpoch milidetik

Token invalid/kadaluwarsa → 401 { "error": "Token tidak valid atau kadaluarsa." }

4 · Ambil 1 dokumen

Termasuk konten markdown mentahnya. Bisa pakai id atau slug.

GET/api/v1/docs/<id-atau-slug>
curl https://markdown.hanif.app/api/v1/docs/catatan-a \
  -H "Authorization: Bearer $TOKEN"
{
  "doc": {
    "id": "m25qh4fjy",
    "title": "Catatan A",
    "url": "https://markdown.hanif.app/catatan-a",
    "slug": "catatan-a",
    "content": "# Catatan A\n\nisi markdown...",
    "theme": "light", "font": "serif",
    "has_passcode": false, "views": 12,
    "created_at": 1780632162730, "updated_at": 1780632162742
  }
}

5 · Replace / edit dokumen

Ganti isi dokumen dengan markdown baru — link-nya tetap sama (id & slug ga berubah). Bisa pakai id atau slug.

PUT/api/v1/docs/<id-atau-slug>

Request body (JSON)

FieldTipeKeterangan
contentstringWajib. Markdown baru (replace penuh)
themestringOpsional — kalau ga dikirim, tema lama dipertahankan
fontstringOpsional — kalau ga dikirim, font lama dipertahankan

Contoh

# replace isi dokumen "catatan-a" dengan file md baru
curl -X PUT https://markdown.hanif.app/api/v1/docs/catatan-a \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d "{\"content\": $(jq -Rs . < catatan-baru.md)}"

Response 200

{
  "ok": true,
  "id": "m25qh4fjy",
  "url": "https://markdown.hanif.app/catatan-a",
  "slug": "catatan-a",
  "title": "Catatan A (v2)",
  "updated_at": 1780640000000
}

Cuma bisa edit dokumen milik akun pemegang token. Bukan punya lo → 401/404. Passcode & slug ga keganti pas replace.

6 · Custom link

Set / ganti / hapus custom link dokumen yang udah ada. Kirim slug kosong buat balik ke link acak.

PUT/api/v1/docs/<id-atau-slug>/slug
curl -X PUT https://markdown.hanif.app/api/v1/docs/k7p2q9m4a/slug \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"slug":"link-baru"}'
{ "ok": true, "slug": "link-baru", "url": "https://markdown.hanif.app/link-baru" }

Udah dipakai → 409. Format salah → 400.

7 · Hapus dokumen

DELETE/api/v1/docs/<id-atau-slug>
curl -X DELETE https://markdown.hanif.app/api/v1/docs/link-baru \
  -H "Authorization: Bearer $TOKEN"
{ "ok": true }

Catatan

  • Semua request JSON pakai Content-Type: application/json.
  • Endpoint /api/v1/auth/token di-rate-limit (anti brute force).
  • Field url udah absolut & siap dibagikan — ga perlu nyusun sendiri.
